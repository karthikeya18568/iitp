# Zepto Data & AI Platform — End-to-End AI/ML Capstone

This repository contains one connected platform with three modules:

1. **`/data_pipeline`** — scrape Books to Scrape, clean and convert catalog data, load a normalized SQLite database, and query it with SQL and pandas.
2. **`/analytics`** — load the Titanic dataset once, clean it once, build the EDA story, train/evaluate three classifiers, compare imbalance strategies, tune Random Forest, complete a fare regression side-task, and save the complete best classification pipeline.
3. **`/support_assistant`** — index eight Zepto policy documents with local SentenceTransformer embeddings in ChromaDB, route queries with LangGraph, return deterministic mock-mode answers, validate structured JSON with Pydantic, and expose the service through FastAPI and Docker.

The capstone requires one public repository containing all three modules and a root README. The repository intentionally uses **one `requirements.txt` per module** so dependencies remain isolated.

## Run the three modules

### 1. Data pipeline

```bash
cd data_pipeline
python pipeline.py
```

Design decisions:

- scrape the first listing page of Fiction, Mystery and Young Adult, giving at least 60 books;
- use `requests` and `BeautifulSoup`;
- use median imputation for numeric parsing failures and drop malformed non-numeric availability rows;
- use the fixed **1 GBP = 105.50 INR** baseline;
- normalize into `categories` and `books` tables with a PK/FK relationship;
- save SQL outputs and reproduce the JOIN with `pd.merge()`.

### 2. Analytics pipeline

```bash
cd analytics
python 01_eda.py
python 02_modeling.py
```

Design decisions:

- the raw Titanic dataset is loaded once through Seaborn when available and immediately committed to `analytics/titanic.csv` as the offline fallback;
- cleaning follows the specified missingness thresholds;
- modeling starts with a stratified split before preprocessing;
- all preprocessing is structurally fit on training data only using scikit-learn pipelines;
- three classifiers and the required imbalance/tuning comparisons are performed;
- the saved classifier artifact contains preprocessing plus the estimator, not just the bare estimator.

### 3. Support assistant

```bash
cd support_assistant
python ingest.py
set MOCK_LLM=1   # Windows CMD; on PowerShell use $env:MOCK_LLM="1"
uvicorn main:app --reload --port 7860
```

Design decisions:

- each required policy document is one retrieval chunk;
- `all-MiniLM-L6-v2` creates local embeddings;
- ChromaDB stores the vectors;
- LangGraph contains `classify_intent`, `retrieve_and_answer`, and `direct_answer` with a conditional route;
- mock mode is the graded baseline and makes no LLM network calls;
- Pydantic validates `answer`, `sources`, and `confidence`;
- FastAPI exposes `POST /ask`;
- Dockerfile provides a locally runnable container baseline.

## Supporting outputs

Charts generated by the analytics scripts are stored under `analytics/outputs/`. The written interpretations are in `analytics/outputs/eda_results.md` and `analytics/outputs/modeling_results.md`; the chart files are supporting artifacts and are not the sole evidence.

## Git workflow

The final public repository must show a feature branch with at least two commits and a merge back into `main`. Example workflow:

```bash
git checkout -b feature/data-pipeline
git add .
git commit -m "Build data extraction"
git add .
git commit -m "Add cleaning and database pipeline"
git checkout main
git merge --no-ff feature/data-pipeline -m "Merge data pipeline feature"
git log --graph --all --oneline
```

The branch/merge requirement is checked across the whole repository, not separately per module.
